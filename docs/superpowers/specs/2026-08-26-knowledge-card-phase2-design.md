## 1. 背景与目标

现有正式知识卡源库位于：

`E:\知识库\追光小牛\专业知识库\训练知识\儿童青少年体适能教练_20260703-20260820\01_知识卡片库`

排除 `README.md` 后共有 1417 张 Markdown 卡片：

| 卡型 | 数量 |
|---|---:|
| 动作卡 | 610 |
| 游戏卡 | 564 |
| 训练计划卡 | 159 |

本期目标不是简单复制文件，而是建设一套可追溯、可隔离、可版本化、可运营的内部知识库，并最终让全部内容对已登录员工可见。

## 2. 已确认的产品决策

1. 采用“扩展现有知识库”架构，不重建 V2，不做旁路双写。
2. 先隔离摄取、完成技术验收，再进入运营审核并最终全量发布。
3. 总体设计分阶段交付，不把摄取、后台和员工端合成一次生产变更。
4. 7 种卡型作为内容类型；8 大专业领域作为主分类；年龄、科目、训练类别、难度、风险作为筛选维度。
5. 旧约 194 条知识保留 ID 和历史关联；新旧内容先生成候选，再由人工确认合并、并存或拒绝。
6. 正文首次由 Markdown 导入；上线后数据库版本为内容主源，后台编辑生成新版本。
7. 最终 1417 张内容全部发布、全体已登录员工可见；风险字段保留但不设置额外访问门禁。
8. 内容后台由 CEO 与指定教学主管编辑、发布、下架和回滚；其他管理者只读；所有操作记录审计日志。
9. 取消整个知识库的“完成学习”和积分入口；历史 `user_knowledge_progress` 不删除，只保留只读历史。
10. 员工端增加收藏和最近浏览，不增加笔记、排行或学习完成率。
11. 不覆盖已上线销售培训卡一期的 `training_modules` / `training_cards` 数据。
12. 任何生产 `--apply` 都必须经过 dry-run 结果审阅和用户明确授权。

2026-08-26 只读核验生产库得到：

- `knowledge_categories`：23 条

- `user_knowledge_progress`：2 条，涉及 1 人，已完成 2 条，累计 120 秒
- `drill_templates`：9 条
- 现有知识全部 `status=1`、`is_public=1`
- 现有员工角色：`ceo`、`coach`、`finance`、`manager`、`operation`、`sales`
- 现有员工阶段：`advanced`、`formal`、`intern`、`probation`、`regular`
- 分类、知识、进度无孤儿记录，进度 `(user_id,knowledge_id)` 无重复

`knowledge_items` 当前没有稳定业务编码、来源哈希、批次、版本或发布历史；现有 API 和演练模板直接依赖自增 ID，因此不得通过删除重插更新旧知识。

## 4. 总体架构

### 4.1 保留的兼容面

- 保留现有 `knowledge_items.id`。
- 保留 `/api/knowledge/list.php`、`detail.php`、`search.php`、旧分类入口及员工端深链。
- 保留 `drill_templates.knowledge_card_id` 和其他历史关联。
- 保留 `user_knowledge_progress` 历史数据，但停止新增和修改写入。

### 4.2 新增能力

- 稳定来源编码：新卡使用源 `card_id`，例如 `ACTION-0001`。
- 批次、来源、版本、候选关系、收藏、最近浏览和审计日志。
- 隔离状态与发布状态分离。
- 受控 Markdown 渲染和受控图片资源。
- 确定性 JSON 包、SHA-256、dry-run、事务、备份、manifest 和精确回滚。

### 4.3 不采用的方案

- 不把 1417 张卡默认拆成销售一期的 K/S/D/C。
- 不把全部内容复制到 `training_cards`、`script_knowledge` 或演练知识图谱。
- 不使用标题自动覆盖旧知识。
- 不使用 `_backup_20260823` 目录作为导入源。
- 不复制历史 `import_faq_knowledge.php` 的硬编码数据库连接模式。

## 5. 数据模型设计

### 5.1 核心表最小扩展

优先在 `knowledge_items` 增加以下字段；如果生产变更窗口不允许扩展核心表，则由同名元数据表提供兼容视图，不能改变旧接口响应：

- `item_code`：稳定业务编码，源卡直接使用 `card_id`
- `content_type`：7 种卡型
- `domain_code`：8 大专业领域编码
- `risk_level`：低/中/高
- `publication_status`：`isolated`、`published`、`offline`
- `source_batch_id`
- `current_version_id`

`status` 继续表示技术启用状态；`publication_status` 表示是否进入员工可见发布面；不得混用。

### 5.2 `knowledge_import_batches`

记录一次导入：

- `batch_id`
- `package_sha256`
- `source_root`
- `parser_version`
- `status`
- `before_counts`、`after_counts`
- `manifest_path`
- `created_at`、`completed_at`

### 5.3 `knowledge_item_sources`

记录来源：

- `knowledge_item_id`
- `source_card_id`
- `source_path`
- `source_sha256`
- `source_articles`
- `source_images`
- `normalized_hash`
- `batch_id`

### 5.4 `knowledge_item_versions`

记录数据库主源版本：

- `knowledge_item_id`
- `version_no`
- 标题、摘要、正文、分类和筛选字段快照
- `change_reason`
- `changed_by`
- `status`
- `created_at`

后台编辑不覆盖历史版本，只创建新版本并更新当前版本指针。

### 5.5 `knowledge_item_relations`

记录新旧内容关系：

- `source_item_id`
- `target_item_id`
- `relation_type`：`candidate`、`merged`、`kept_separate`、`rejected`
- `reviewed_by`
- `reviewed_at`
- `review_note`

人工合并时保留旧知识 ID、历史进度和演练关联；新来源挂到旧项的新版本。未合并内容创建新知识项。

### 5.6 个人与审计表

`knowledge_favorites`：使用 `(user_id, knowledge_id)` 唯一约束，支持收藏/取消收藏。

`knowledge_recent_views`：使用 `(user_id, knowledge_id)` 唯一约束，记录最近查看时间和次数。

`knowledge_audit_logs`：记录导入、编辑、合并、发布、下架、回滚及操作者；日志不可由普通后台操作删除。

## 6. Markdown 解析与内容契约

### 6.1 解析规则

- 只读正式源目录，排除 README 和备份目录。
- 每个 Markdown 文件默认对应一个知识项，不沿用 K/S/D/C 拆分。
- `card_id`、`card_type`、`status`、`risk_level`、正文和来源必须存在。
- `教学知识`作为正式第七种类型，不被旧 README 的三类枚举限制。
- “原文未说明”保留为结构化缺失标记，不伪造年龄、器材或来源。
- `source_articles`、`source_images` 原样保留并进行 URL 占位、路径和文件存在性检查。
- 解析器输出稳定字段排序和稳定 JSON 编码，保证同一输入字节级一致。

### 6.2 内容清洗

允许渲染：标题、段落、列表、表格、引用、`https` 链接和受控图片。

禁止：原始 HTML、脚本、事件属性、`javascript:`/`data:` 链接、未验证本地路径和任意外链图片直出。

原始 Markdown 和规范化内容同时保存在来源/版本记录中；员工端只渲染受控内容。

### 6.3 质量报告

导入前必须生成：

- 1417 张总量和 7 类分布
- ID 唯一性和连续性
- frontmatter 完整性
- 低/中/高风险精确计数
- 占位 URL 和缺失来源
- 标题、正文规范化哈希
- 与旧194条的精确/高相似候选
- 已知 P1/P2 与审计标记
- 每个模块/领域/类型的数量

质量报告只用于隔离和人工决策，不把 `status: 已审核`自动解释成专业审核通过。

## 7. 权限与运营后台

### 7.1 员工端

- 所有已登录员工可查看已发布内容。
- 未登录用户不能访问列表、详情、收藏或最近浏览。
- 角色和阶段以服务端当前身份为准，拒绝客户端伪造筛选身份。
- 详情中的“相关知识”必须再次执行可见性校验。
- 风险字段展示但不设置额外查看门禁。

### 7.2 后台能力

使用显式能力控制，不仅依赖 `manager` 角色：

- `knowledge_view`：管理者及以上
- `knowledge_edit`：CEO、指定教学主管
- `knowledge_publish`：CEO、指定教学主管
- `knowledge_rollback`：CEO、指定教学主管
- `knowledge_audit`：管理者及以上

指定教学主管通过明确的后台权限配置绑定员工 ID，不自动授予所有 manager 发布权。

后台支持：批次报告、来源和风险查看、旧卡候选确认、编辑新版本、批量发布/下架、版本历史、指定版本回滚和审计查询。

## 8. 学习、积分与个人功能

### 8.1 取消完成与积分

整个知识库移除“完成学习”和知识积分入口。

- `progress.php` 的历史 GET 兼容读取保留。
- POST `complete` / `update` 不再写入，返回明确的功能停用响应。
- 不删除已有 `user_knowledge_progress`，不修改月度统计历史。
- 不再调用完成奖励积分逻辑。

### 8.2 收藏与最近浏览

- 收藏和取消收藏必须验证知识已发布且当前用户已登录。
- 最近浏览只记录已发布知识的查看事件。
- 收藏与最近浏览不等同于学习完成，不产生积分。
- 下架内容从员工端隐藏，但个人历史记录保留用于审计。

## 9. 分阶段交付

### 阶段 0：生产基线与只读分析

只读获取表结构、索引、行数、分类、角色阶段、进度和关联快照；生成 1417 张源卡质量报告及旧194条候选报告，不修改生产。

### 阶段 1：安全基础与隔离摄取

修复知识接口边界，关闭完成/积分写入，创建元数据表，生成确定性 JSON，导入 1417 张为 `isolated`，实现 dry-run、备份、事务、manifest、幂等和精确回滚。阶段验收要求隔离内容不可被员工端查询。

### 阶段 2：运营后台与人工合并

实现批次报告、旧卡候选确认、合并/并存/拒绝关系、版本编辑、发布/下架/回滚和审计。阶段验收要求旧 ID、进度、演练关联不变且操作可追溯。

### 阶段 3：员工端全量发布

发布 1417 张及人工确认后的内容；实现领域、卡型、年龄、科目、训练类别、风险筛选、受控正文媒体、收藏和最近浏览；保留旧 URL 和响应结构。阶段验收要求全员可见且无学习积分写入。

每个阶段单独提交、单独测试、单独 dry-run；不将三阶段合并为一次生产变更。

## 10. 测试与生产门禁

### 自动化测试

1. 解析：1417 张、7 类、ID 唯一、frontmatter 完整。
2. 数据包：字节确定性、SHA-256、正文哈希和枚举。
3. 导入器：dry-run 无数据库写、幂等、冲突阻断、事务和回滚。
4. 权限：匿名拒绝、员工只读、后台能力矩阵、旧接口 IDOR。
5. 安全渲染：XSS、HTML、URL、图片路径和表格边界。
6. 进度：POST 禁止写入，历史数据保持不变。
7. 完整性：旧194条、演练关联、历史 ID 和进度不变。
8. 收藏/最近浏览：登录、发布状态和唯一约束。
9. PHP 7.4 语法与真实生产 PHP/PDO 只读验证。

### 生产门禁

- 先比较线上文件和仓库基线，禁止盲目覆盖。
- 生产数据包、备份、manifest 位于 Web 根目录外且权限为 0600。
- 默认 dry-run；`--apply` 必须显式指定。
- apply 需要命名锁、导入前备份、事务、非目标行摘要断言和 completed manifest。
- apply 后必须再次 dry-run，期望 insert/update 为 0、目标项全部 skip。
- 必须执行 rollback dry-run；rollback apply 仍需独立确认。
- 任何报告“数据库已提交但文件写失败”必须明确标识已提交，不得诱导重试。

## 11. 明确不在本规范内

- 不处理销售培训卡一期已上线的 300 张卡。
- 不处理演练知识图谱的全量重构。
- 不建立员工笔记、评论、排行或推荐算法。
- 不做自动专业审核或自动风险降级。
- 不把相似内容自动合并。
- 不在本设计获用户书面审阅前创建数据库表、修改 API 或生成生产导入包。

## 12. 成功标准

- 1417 张源卡可追溯到源文件、SHA-256、解析器版本和导入批次。
- 无稳定编码冲突、孤儿关系或不可解释的重复。
- 旧194条的 ID、深链、进度和演练关联不变。
- 隔离阶段不可见，发布阶段全部已登录员工可见。
- 风险字段完整保留，风险内容不被无意改写。
- 知识库不再新增完成记录或积分奖励，历史数据可读。
- 收藏和最近浏览可用且不产生积分。
- 后台版本、发布、回滚和审计可追溯。
- 任意导入批次可重跑、可审计、可精确回滚。
- 每个生产 apply 均有用户明确授权和验收记录。
