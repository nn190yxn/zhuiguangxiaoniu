# 知识卡二期任务9：员工端知识库全量检索阅读设计

作者: Monkeycode

## 背景

任务5至8已经完成知识卡发布态边界、个人收藏/最近浏览、受控渲染和运营后台能力。任务9聚焦员工端阅读体验：把知识库从“学习完成/积分”导向，改造成可搜索、可筛选、可收藏、可回看最近浏览的全量阅读入口。

## 目标

1. 小程序与移动 H5 双端同步升级。
2. 保留现有列表、详情、搜索和深链入口。
3. 增加类型、专业领域、年龄、科目、训练类别、难度和风险筛选。
4. 显示收藏状态，并提供收藏列表与最近浏览入口。
5. 详情页只保留阅读、收藏、相关知识和演练入口，不再展示完成学习、完成率、积分奖励主流程。
6. 所有员工端接口继续只返回 `status=1 AND publication_status='published'` 的知识。

## 非目标

- 不执行生产导入、发布、回滚或迁移。
- 不新增员工端编辑能力。
- 不展示隔离、下架或审核中知识正文。
- 不重写整套前端框架。

## 方案选择

采用“共享接口增强 + 双端同步改造”。

- 后端继续复用 `knowledge/list.php`、`detail.php`、`favorite.php`、`recent-views.php`。
- `KnowledgeListService` 继续作为列表筛选中心。
- 小程序和 H5 使用同一套 query 参数语义。
- 双端页面各自按当前结构最小改造，不抽象新框架。

## 后端契约

### 列表参数

`GET /knowledge/list.php`

支持：

- `keyword`
- `type`
- `category_id`
- `subject`
- `age_group`
- `training_type`
- `content_type`
- `domain_code`
- `difficulty`
- `risk_level`
- `favorite=1`
- `recent=1`
- `page`
- `page_size`

约束：

- `favorite=1` 只返回当前登录用户收藏且仍发布的知识。
- `recent=1` 只返回当前登录用户最近浏览且仍发布的知识，按最近浏览时间排序。
- `favorite` 和 `recent` 同时传入时，优先 `favorite`。
- 所有筛选都只在发布态知识内执行。
- `LIMIT` 参数使用整数绑定。

### 列表返回

列表项补充：

- `is_favorite`
- `last_viewed_at`
- `content_type`
- `domain_code`
- `difficulty`
- `risk_level`
- `updated_at`

### 详情返回

`GET /knowledge/detail.php` 保持历史字段兼容，补充阅读展示元信息：

- `is_favorite`
- `recent_view`
- `version_updated_at`：优先当前版本更新时间，缺失时使用知识更新时间。
- `display_meta`：类型、领域、科目、年龄、训练类别、难度、风险。

详情仍然只允许发布态知识。

## 小程序设计

### 列表页

- 顶部保留搜索框。
- 增加快捷筛选：全部、收藏、最近浏览。
- 增加可收起高级筛选面板：
  - 类型
  - 专业领域
  - 科目
  - 年龄段
  - 训练类别
  - 难度
  - 风险
- 卡片展示：标题、摘要、类型/领域/风险/收藏状态、更新时间。
- 支持分页加载，切换筛选时重置分页。

### 详情页

- 移除“学习完成”“已经学完”“完成率/积分”主流程按钮和文案。
- 保留收藏/取消收藏按钮。
- 保留正文、来源元信息、相关知识、演练入口。
- 进入详情后继续记录最近浏览。

## 移动 H5 设计

与小程序语义一致：

- 搜索框 + 快捷筛选 + 可收起高级筛选面板。
- 列表卡片显示收藏状态、风险、领域和更新时间。
- 详情页阅读化，移除完成/积分按钮。
- 收藏按钮调用 `favorite.php`，最近浏览列表走 `recent-views.php` 或 `list.php?recent=1`。

## 错误处理

- 未登录：沿用现有页面认证跳转。
- 空列表：显示当前筛选无结果，并提供“清空筛选”。
- 接口失败：显示重试入口。
- 收藏失败：不乐观写入最终状态，以服务端返回为准。
- 下架历史浏览：最近浏览接口可保留历史记录，但列表/详情不展示下架内容正文。
