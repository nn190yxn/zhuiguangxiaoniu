# 测试与发布门禁

仓库在 `scripts/` 提供 Node.js 和 PHP 自动化脚本，覆盖平台、组织、工作量、演练、小程序、认证、migration、招聘、PWA 和静态契约。

## 测试类型

| 类型 | 命名 |
|------|------|
| 示例与回归测试 | `*.test.mjs`、`*_test.php` |
| 属性测试 | `*.property.test.mjs` |
| migration 验证 | `migration_*.test.mjs`、`migration-replay.php` |
| 发布门禁 | `unified_release_gate*.mjs`、`platform_release_gate*.mjs`、`platform_preflight*.mjs` |
| 静态审计 | `audit_*.php`、`check_*.mjs` |

## 运行原则

1. 根据改动域运行最小相关测试。
2. 跨平台能力改动运行对应契约和属性测试。
3. migration 同时验证兼容性、幂等、readiness 与 replay。
4. 小程序页面完成自动测试后仍需开发者工具验证。
5. 公开内容运行 JSON-LD、FAQ、链接、sitemap 和 HTTP 检查。

`migration_runner.test.mjs` 使用内存数据库覆盖首次 dry-run，验证历史表保持缺失、业务行值不变、前后快照相等，并确认待执行 migration 只返回 `would_apply`。其中 Property 5 使用 18 组确定性初始状态改变业务表数量、索引、行数、空值、历史表存在性和已应用记录，逐组比较完整 SQLite schema、逐行数据与 runner 快照，证明 dry-run 零结构、零数据变化。

`migration_mysql.integration.test.mjs` 验证真实 MySQL 回放入口的安全边界和六阶段合同。配置专用数据库后，PHP harness 从包含课程表等旧版依赖的 baseline 开始，使用全库结构、行数和 table checksum 指纹证明 dry-run 零变化，再执行 68 个 migration、verify、结构与数据 readiness、组织及工作量回填、知识及教案版本归属、正式教案库状态、签到日期回填、关键复合外键和二次 apply；数据库名、确认口令或空库条件不满足时立即终止。完整 migration 检查点当前包含 42 项测试，真实 MariaDB 回放执行时要求零失败、零跳过。

`migration_compatibility.test.mjs` 验证 SQL 风险分类，覆盖 `MODIFY COLUMN`、`UPDATE`、`INSERT`、状态字段回填、引擎或字符集导致的潜在表重写，并排除注释和字符串中的伪关键词。确定性分类矩阵运行 24 组语句顺序、大小写、块注释、行注释和反引号变体，要求风险类型、目标、来源稳定且无重复。测试同时验证风险声明缺项会返回版本、SQL 风险类型、目标、语句序号和缺失字段，完整 forward-fix 声明可通过兼容门禁。

该测试还固定 `202609040002` 的专用风险声明与 SQL 边界，包括 `knowledge_item_id` 保持可空、只回填 `source_type = 'knowledge_card'` 且 `knowledge_version_id IS NULL` 的记录，以及知识版本复合外键继续指向 `knowledge_item_versions(knowledge_item_id, version_id)`。`migration_readiness.test.mjs` 同时要求其余 migration 保持统一保守基线。

`knowledge_version_consistency.property.test.mjs` 验证知识版本一致性 Property 7。测试使用 256 个固定种子生成 4096 条知识主记录及其 active、superseded、rolled_back、空 current version、无效 current version 和跨知识卡版本组合，通过 SQLite 实际执行 `EmployeeKnowledgeVisibilityQuery`；每个可见结果必须返回属于自身的 active 当前版本。生产接线断言同时覆盖知识列表、详情、相关内容、全局搜索和教案知识建议的版本 ID。

`knowledge_taxonomy_mapping_contract.test.mjs` 验证版本化分类映射源。测试要求存在唯一激活版本，专业知识与销售知识两条主线及其稳定子分类完整，激活版本的 domain code 集合与 1417 张知识卡导入包完全一致，七类内容复核基线完整，并逐项验证目标主线和子分类有效。`knowledge_taxonomy_mapping.property.test.mjs` 使用 256 组固定种子验证 PHP domain 映射归一化，使用 24 组记录顺序扰动验证分类审核语义与稳定排序，并逐条确认正式 1417 张卡命中激活映射和有效分类目标。`knowledge_card_classification_report.test.mjs` 验证正式报告输入摘要、1417 条逐卡审核状态、1404 条分类差异、人工确认原因、确定性输出、映射缺口和异常 taxonomy；`knowledge_taxonomy_contract.test.mjs` 通过 PHP 运行时验证领域映射优先级、旧销售内容兼容筛选和统一版本字段。

`knowledge_card_release_gate.test.mjs` 通过 PHP CLI 执行 `knowledge-card-release-gate.v2`，验证记录数、过渡分类、映射、current version、审核记录和目标可见数量六项独立结果及稳定失败原因。测试包含完整通过 fixture、六类单项失败、目标 evidence 缺失和正式 1417 卡待审核阻断场景。`unified_release_gate.test.mjs` 同时要求 release evidence 提供 `current_version_count`、`review_record_count` 和 `taxonomy_mapping_version`，验证可见数量与总量不一致、版本或审核数量不完整和 mapping 版本缺失的阻断结果，并以数据库证据变化矩阵证明仓库知识包状态保持独立。

知识分类与发布边界检查点组合运行版本一致性、共享可见性、taxonomy、分类报告、1417 卡包与只读门禁、全局搜索、桌面知识页、教案知识匹配和统一门禁测试。仓库内完整测试集当前包含 69 项，其中 67 项通过；正式源质量报告与正式源重建两项依赖外部 `KNOWLEDGE_SOURCE_ROOT`，该目录提供后可执行到零跳过。检查点同时对 10 个知识与搜索 PHP 消费者和关键 Node 脚本执行语法检查。

## 统一发布门禁

`unified_release_gate.mjs` 为正式放行聚合入口，独立输出 `page-contract`、`database-integration`、`browser-integration`、`knowledge-package-state`、`knowledge-database-state` 和 `release-evidence-current`。release evidence 的机器可读结构位于 `release-evidence.schema.json`，包含被验证文件及代码摘要、完整 migration 集合、测试总数、数据库 migration 结果、普通员工与三类管理角色流程、数据库知识总量与可见数量、过渡与未映射数量、current version 与审核记录数量、taxonomy mapping 版本、静态资源发布号和证据有效时间。

门禁通过 `--evidence <path>` 或 `RELEASE_EVIDENCE_PATH` 读取 evidence。相关文件摘要、migration 集合或有效时间发生变化后，`release-evidence-current` 会失败；`--integration-verified` 需要当前数据库和浏览器证据共同通过。最终 `ready_for_release=true` 表示全部必需检查及其他已执行检查均通过。

## 教案测试

教案测试覆盖 Office 解析与手工录入回退、结构化版本、ACE 规则、知识卡建议、上传编辑页面、建议决定、版本比较和智能教案资料源。`lesson_submission_editor_contract.test.mjs` 检查解析端点、页面字段、接口串联、建议采纳或忽略、状态版本、版本差异和员工入口；`lesson_submission_identity_contract.test.mjs` 固定共享身份适配器、只读作者显示、认证姓名请求来源和服务端 staff ownership；`lesson_suggestion_version.property.test.mjs` 使用固定随机种子验证建议始终绑定生成时教案版本；`lesson_database_state.property.test.mjs` 验证当前版本、批准版本、审核、导出、审计及建议均属于同一教案，并验证知识建议固定到同一知识卡的具体版本。

`lesson_library_api_contract.test.mjs` 验证正式教案列表和详情端点只读取已批准、已发布、已提交且不可变的批准版本，并固定认证、migration readiness、统一平台响应和规范路由契约。`platform_business_domain_migration.test.mjs` 验证 `lesson_review` 域登记正式库页面和脚本消费者，并声明批准版本发布、正式库读取和规范路由能力；该测试中的知识可见性回归同时验证列表、详情和搜索通过共享当前版本组件读取已发布知识。`lesson_library_query_service.test.php` 通过 SQLite 实际执行查询，覆盖稳定分页、课程线与班级筛选、关键词筛选、脏状态隔离、批准版本与后续草稿分离，以及隐藏详情的稳定 404。`lesson_library_page_contract.test.mjs` 验证页面使用正式库列表与详情接口、卡片采用规范路由、URL 参数加载批准详情、四类页面状态及学习中心入口。`lesson_archive_contract.test.mjs` 与 `lesson_archive_service.test.php` 验证主管权限、状态版本锁、事务回滚、批准版本有效性、活跃发现移除及版本、审核、导出、发布历史和审计引用保留。

`lesson_lifecycle_e2e.test.mjs` 是教案生产服务的自动化端到端入口。Node 编排器创建临时 SQLite 数据库和 DOCX，通过 PHP 内置 HTTP 服务发送真实 multipart 上传，再顺序调用生产服务完成解析、草稿版本、ACE 校验提交、两级审核、批准版本发布、正式库列表与详情和归档；测试要求状态版本从 1 递增到 7，并验证归档后正式库隐藏且版本、原文件、解析运行、审核任务和审计记录继续保留。

`lesson_approved_version_consistency.property.test.mjs` 是正式库批准版本一致性的数据库属性测试入口。PHP harness 使用真实 SQLite 和生产 `LessonReviewDecisionService`、`LessonLibraryQueryService` 生成 256 个确定性终审样本，逐项检查主管任务版本、审核响应、主记录批准版本、正式库列表与详情；85 个样本在批准后切换当前草稿版本，结果仍要求正式库固定读取原批准版本且不产生任何不一致。

教案全链路检查点组合全部 `*lesson*.test.mjs` 与平台幂等契约和属性测试，当前基线包含 94 项 Node 测试，覆盖教案权限、版本关系、重复请求、两级审核、正式库、归档和 Office 解析导出。门禁同时要求全部教案 PHP 文件语法、正式库 JavaScript 语法、正式库查询 SQLite 测试和归档 SQLite 测试通过。

## 副作用数据库集成测试

`critical_side_effects_mysql.integration.test.mjs` 调用 PHP harness 连接名称明确标识为测试用途的 MySQL 数据库。该 harness 使用两个独立连接制造并发请求，并为积分兑换、每日签到、考试提交、教案创建和教案导出各执行一次完成后重试。验收结果要求 5 类检查、15 次请求全部成功，且每类业务表只提交一份结果。测试数据库和私有导出目录保留运行记录，便于发布证据复核。
