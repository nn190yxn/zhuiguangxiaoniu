# 技术设计：销售流程驱动的自由演练

## 1. 设计目标

在现有自由演练、场景版本快照和演练阶段状态机基础上，补充阶段规则上下文，使 AI 客户问题围绕当前销售阶段生成，并让授权失败状态在小程序界面可见、可操作。

## 2. 现有结构复用

- `drill_scenario_versions` 已保存 `objectives_json`、`key_actions_json`、`standard_expressions_json`、`risk_expressions_json` 和 `prompt_policy_json`。
- `drill_attempts` 已保存场景、流程、评分和校准版本快照。
- `drill_attempt_stage_progress` 已保存当前阶段及阶段顺序。
- `DrillConversationService::practiceContext()` 已向客户端返回场景与当前阶段上下文。
- `DrillAiAdapter::generateCustomerTurn()` 继续作为 AI 客户回应的唯一入口。

## 3. 销售 Skill 板块核心矩阵

训练规则必须以“核心目标 -> 必须说到 -> 禁忌说到 -> 标准表达 -> 可验证动作”的结构保存。以下矩阵来自新签 Skill、首次到店接待标准和销售手册，作为首版默认规则；运营可以在新版本场景中补充细节。

| 板块 | 核心目标 | 必须说到的内容 | 禁忌说到的内容 | 标准表达方式 | 对应 Skill 核心 |
|---|---|---|---|---|---|
| 线索准备 | 明确线索来源、孩子背景和本次沟通目标 | 来源、孩子基本情况、家长初始诉求、下一沟通目标 | 编造线索信息、提前承诺效果或优惠 | 先确认已知信息，再用一个开放问题补齐未知信息 | 需求挖掘 |
| 邀约确认 | 把意向变成明确到店安排 | 时间、地点、穿着、提前到店体测、三方服务群、再次确认节点 | 模糊时间、虚假名额、强迫到店、承诺结果 | “确认安排 + 到店准备 + 体测价值 + 下一次确认” | 需求挖掘、紧迫感 |
| 到店接待 | 建立信任并完成体验前需求沟通 | 主动叫名、签到、环境介绍、孩子状态、家长关注点 | 冷落家长、只讲门店、医学化判断、贬低竞品 | 先接待和观察，再复述家长关注点并确认体验目标 | 需求挖掘 |
| 需求诊断 | 问清购买动机、核心痛点、竞品经历和决策链 | 至少覆盖三类需求问题，并复述确认核心问题 | 只问年龄住址、连续自说、替家长定义需求 | “我先了解原因和目标，再根据孩子情况给建议” | 需求挖掘 |
| 体测与体验协同 | 把观察结果转成家长听得懂的基础能力问题 | 看见的表现、基础能力、学习生活影响、训练方向、教练反馈 | 越位诊断、疗效保证、绝对化结论、用焦虑吓唬家长 | “观察表现 -> 基础解释 -> 影响 -> 课程承接” | 方案匹配与规划 |
| 方案与价值呈现 | 把需求转成可理解、可执行的方案价值 | 痛点、课程特征、真实案例、孩子收益、ACE 背书、训练计划 | 只讲课程表、未经核验的数字、夸大效果、先报低价 | “痛点 -> 特征 -> 案例 -> 价值 -> ACE 背书” | FAB 转化、案例植入、方案规划 |
| 异议及签约交接 | 识别隐形异议、解决顾虑并推动下一步 | 孤立担忧、确认异议、解决方案、报价依据、试关闭、成交交接信息 | 争辩、未经授权降价、回避异议、恐吓式紧迫感 | “理解 -> 追问 -> 孤立 -> 解决 -> 确认 -> 试关闭” | 异议处理、报价谈判、试关闭、紧迫感 |
| 未成交跟进与转介绍 | 让未成交客户进入明确跟进节奏并保留信任 | 当天感谢、体验资料、24 小时顾虑回访、3/7/15/30 天节点、下一次联系时间 | 群发骚扰、虚假优惠、泄露案例隐私、无计划地反复催促 | “总结体验 -> 发送资料 -> 确认顾虑 -> 约定时间 -> 按节点跟进” | 异议处理、紧迫感 |

每个板块至少配置一组正例、一组反例和一组可直接复述的标准表达。涉及品牌数字、效果数字、案例和价格的表达必须绑定经过审核的资料版本。

## 4. 客户回合生成

### 4.1 输入上下文

`submitTextTurnWithGeneratedCustomer()` 组装以下结构传给 AI：

- `customer_profile`：固定的家长画像快照。
- `scenario_goal`：本次演练目标和选择条件。
- `scenario_rules`：场景目标、关键动作、标准表达、风险表达和 prompt policy。
- `current_stage`：阶段 ID、编码、名称、排序和当前状态。
- `history`：最近若干轮已完成对话。
- `stage_prompt_contract`：当前板块的核心目标、must_say、must_avoid、standard_expressions、validation_actions 和 practical_next_steps。

### 4.2 生成约束

系统提示要求 AI：

- 只返回 `response`、`intent`、`target_action` 和 `stage_code`。
- 客户问题必须符合客户画像和当前阶段。
- 优先验证尚未覆盖的关键动作。
- 禁止替员工完成销售动作或直接给出标准答案。
- 禁止编造场景外的课程、价格、政策和承诺。
- 客户问题需要逼近一个可验证动作，例如追问购买动机、暴露预算顾虑或要求确认下一步。

### 4.3 失败降级

当 AI 返回空内容或不可解析 JSON 时，服务端从当前阶段的 `prompt_policy.fallback_questions`、`standard_expressions` 或阶段名称生成确定性问题。兜底内容写入生成元数据，便于反馈页识别本轮是否使用降级逻辑。

## 5. 文字回复检查与务实建议

文字回复提交后，反馈链分为四层：

1. `coverage`：检查 must_say 是否覆盖，并关联对应 key action。
2. `risk`：检查 must_avoid、未经核验数字、医学化表达、绝对化承诺、贬低竞品和恐吓式表达。
3. `script_match`：检查是否使用当前板块的标准表达结构，而非只匹配关键词。
4. `practical_next_step`：输出下一句可直接使用的话术和下一步动作，例如继续追问、确认顾虑、给出方案、发资料或约定回访时间。

AI 反馈需要引用员工原文。AI 服务失败时，确定性规则至少返回缺口、风险命中和一个替代表达。

测试回放覆盖以下文字场景：需求诊断、体测解读、FAB 价值呈现、价格异议、回去考虑、试关闭和未成交跟进。每个场景同时准备“可兜住回复”和“缺失或违规回复”，测试结果需要证明系统能给出具体建议。

## 6. 阶段推进

第一版沿用现有阶段状态机和手动推进接口。客户回合生成与阶段推进保持解耦：本次改动先让每轮提问读取当前阶段规则，再由现有阶段接口完成阶段切换。评分服务使用已保存的场景快照和评分规则快照，保证历史演练可复盘。

## 7. 小程序上下文展示

自由演练开始后，在聊天头部展示当前阶段名称和训练目标；后端返回的 `practice_context.scenario` 增加 `key_actions`、`risk_expressions`，客户端保留现有消息展示结构并增加阶段提示卡。阶段切换后通过恢复接口刷新阶段上下文。

## 8. 隐私授权状态

### 6.1 状态模型

隐私工具返回结构化结果：

- `authorized`：是否满足录音条件。
- `privacy_status`：`authorized`、`required`、`failed`、`unsupported`。
- `record_status`：`authorized`、`required`、`denied`、`unsupported`。
- `action`：`none`、`open_privacy`、`open_settings`。

### 6.2 交互流程

1. 用户点击录音按钮。
2. 直接调用隐私指引授权 API。
3. 隐私指引成功后检查 `scope.record`。
4. 系统权限被拒绝时显示说明，并提供打开设置入口。
5. 隐私授权失败时显示说明，并提供查看隐私指引入口。
6. 文字输入始终可用。

录音按钮继续支持长按录音，但授权检查结果需要在页面中保存，避免每次失败只显示相同 Toast。

- `api/drill/v2/services/DrillConversationService.php`
  - 补充场景规则和当前阶段详情。
  - 返回自由演练阶段训练上下文。
- `api/drill/v2/services/DrillAiAdapter.php`
  - 扩展客户回合输入和系统约束。
  - 优化阶段相关确定性兜底问题。

  - 返回结构化授权状态和失败动作。
- `mini-program/pages/drill/free-chat/free-chat.js`

  - 根据授权结果展示隐私指引或系统设置操作。

  - 增加阶段提示卡和授权状态操作区。
- `mini-program/pages/drill/free-chat/free-chat.wxss`
  - 增加阶段提示卡和授权提示样式。

## 10. 验证方案

- PHP 语法检查。
- 小程序 JavaScript、WXML 契约检查。
- 客户回合输入包含场景规则和当前阶段详情的单元测试。
- AI JSON 失败时使用阶段兜底问题的单元测试。
- 8 个销售板块均存在三段式提示词契约的完整性测试。
- 文字回复回放测试验证覆盖、风险、标准表达和务实建议。
- 隐私授权成功、隐私授权失败、录音权限拒绝和文字降级路径测试。
- `git diff --check`。
