# 知识卡内容增强实施计划

## 一、基础能力收口

- [x] 1. 建立增强内容数据模型和版本边界
  - 保存 `knowledge_item_id`、`source_version_id`、`source_content_sha256`、增强稿哈希、状态和审核审计信息，满足需求1.1、需求4.4。
  - 明确原文、增强稿、发布稿的独立读取关系，满足需求1.3、需求6.2。
  - 为空正文、短正文、历史版本和源版本变化定义状态，满足需求1.2、需求2.4。
  - 编写数据结构、外键和哈希校验测试，覆盖设计属性1、2。

- [x] 2. 实现原文质量扫描和任务分层
  - 检查正文长度、段落、摘要、步骤、教练提示和安全说明，满足需求2.1、2.2。
  - 按动作、感觉统合、体能、教学方法、儿童发展和家长沟通六类生成任务。
  - 保留标题、摘要、正文、标签、分类、源版本和正文哈希作为任务输入。
  - 编写重复扫描稳定性测试，覆盖需求2.3和设计属性1。

- [x] 3. 实现分类型增强模板
  - 为动作卡生成目标、准备、步骤、教练提示、常见错误、难度调整和安全边界。
  - 为感觉统合卡生成感觉目标、输入方式、观察反应、调节方式、课堂支持和专业边界。
  - 为体能卡生成训练目标、强度、组数、时间、休息、进阶标准和停止条件。
  - 为教学方法、儿童发展和家长沟通卡生成适用场景、流程、观察指标、家庭建议或沟通示例。
  - 保持内部字段键稳定，并使用员工可直接照读和执行的平实中文标签，满足需求3.1至需求3.4。

- [x] 4. 实现增强稿生成和事实约束
  - 使用完整后台原文生成结构化草稿，并保存可定位的原文引用片段。
  - 对原文未明确的训练参数、医学判断、发育结论和安全建议标记人工确认，满足需求4.1、4.2。
  - 支持幂等生成、失败状态、失败原因、重试次数和单卡错误记录。
  - 编写事实引用、敏感内容、失败恢复和幂等性测试。

- [x] 5. 完成后台审核工作台
  - 支持按状态、内容类型、风险标记、正文长度和主题筛选，满足需求5.1。
  - 支持原文、增强稿、引用和风险标记对照查看，满足需求5.2。
  - 支持字段级编辑、保存草稿、通过、退回、审核意见和并发版本冲突处理，满足需求5.3、需求5.4。
  - 保存审核人、审核时间、审核意见、审核前后哈希和审计日志。
  - 编写权限、状态流转、并发审核和审计记录测试。

- [x] 6. 接入员工端详情和列表
  - 详情页优先展示哈希一致的已发布增强稿，并保留“查看原文”入口，满足需求6.1、需求6.2。
  - 员工端使用“先了解原理 → 再照着做 → 最后看重点”的展示顺序。
  - 待审核、生成失败、源版本过期或正文为空时回退原文并显示状态，满足需求6.3。
  - 列表页使用增强摘要，增强摘要缺失时回退现有摘要逻辑，满足需求6.4。
  - 编写接口权限、版本读取、回退逻辑和安全渲染测试。

- [x] 7. 实现发布、回退和批量报告
  - 创建独立发布批次和快照，发布前校验知识ID、版本ID、正文哈希、增强稿哈希、引用完整性和审核状态，满足需求7.1。
  - 校验失败的记录留在原状态并记录具体原因，满足需求7.2。
  - 支持单卡、批次和全量批次回退，保留增强稿、审核记录和发布审计，满足需求7.3。
  - 输出成功、待审核、失败、风险和回退数量，满足需求7.4。
  - 编写发布门禁、哈希冲突、批次覆盖和回退幂等属性测试。

## 发布阻断条件

- [ ] 21. 处理全量发布阻断项
  - [ ] 21.1 任一记录源版本不存在或正文SHA256不一致时，阻断该记录发布并标记 `stale`。
  - [ ] 21.2 任一增强稿缺少原文引用、风险确认或审核记录时，阻断该记录发布。
  - [ ] 21.3 任一批次报告计数不守恒或快照哈希不一致时，暂停后续批次。
  - [ ] 21.4 员工端接口出现草稿泄露、权限越界或原文无法回退时，立即回退受影响批次。
  - [ ] 21.5 生产健康检查、数据库迁移或关键回归测试失败时，保留当前线上版本并停止正式发布。
