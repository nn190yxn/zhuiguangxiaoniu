# 全站正常使用审计方案

Feature Name: full-site-audit
Updated: 2026-09-08

## 方案

审计采用四层证据：仓库资产清单、自动化契约测试、隔离测试账号的浏览器实测、生产环境接口与业务冒烟。每一层输出可追溯证据，下一层验证上一层无法证明的运行时行为。

## 审计批次

1. 资产盘点：页面、入口、脚本、接口、数据库表、migration、云函数和现有测试映射。
2. 认证基础：登录方式、redirect、刷新、退出、密码、设备、锁定、会话撤销和多标签页。
3. 员工端：工作台、工作量、学习、课程、考试、制度、知识、演练、我的、消息和工具。
4. 管理端：仪表盘、员工组织、权限、工作量、学习、演练、招聘、知识、教案审核、系统健康和操作日志。
5. 内容与业务工具：公开官网、课程资料、体测、夏令营、动作库、搜索、导入、导出和媒体。
6. 小程序与适配层：页面生命周期、登录绑定、业务矩阵、direct/cloud/shadow、代理签名、媒体和失败恢复。
7. 数据与接口：响应契约、权限矩阵、幂等、状态机、异步任务、SQL、migration 和审计留痕。
8. 兼容与生产：桌面、手机、平板、PWA、缓存、反向代理、静态资源和生产冒烟。

## 测试账号

优先使用现有账号覆盖销售、教练、店长、总部运营和超级管理员。缺失角色时创建 `AUDIT_` 前缀账号，绑定隔离门店和明确测试数据。所有测试账号建立账号表、角色、门店、初始状态、密码交接、会话版本和清理策略，测试过程禁止使用正式客户数据。

## 单个用例格式

每个用例包含：ID、业务域、角色、设备、入口、前置数据、操作步骤、预期页面状态、预期请求、预期数据变化、错误恢复、证据位置、结果和缺陷编号。关键写流程至少验证首次提交、重复提交、刷新后提交、网络中断恢复、过期会话和权限变化。

## 核心正确性属性

- 登录成功后，目标页面的认证请求使用同一有效会话。
- 账号停用或会话撤销后，旧令牌无法访问受保护资源。
- 门店员工只能读取和写入授权门店范围。
- 重复写请求最多产生一次业务结果。
- 状态版本冲突保留权威服务端状态并提供恢复动作。
- 正式内容只展示已发布且版本关系一致的数据。
- 导出、媒体和证据资源遵循访问者权限及私有存储边界。
- migration 二次执行不会重复写入或破坏已有数据。

## 自动化与人工分工

自动化负责页面契约、脚本依赖、API 结构、PHP 语法、权限静态规则、状态机、migration、数据属性和回归测试。人工浏览器负责视觉状态、真实登录、表单体验、空数据、错误提示、跳转、录音权限、文件选择、PWA 安装和跨页面恢复。生产验证只执行可回滚或只读检查及隔离测试数据写入。

## 通过标准

批次通过需要：核心用例全部通过，P0/P1 缺陷为 0，P2 缺陷有明确修复计划；所有 API 契约和现有回归测试通过；认证、权限、幂等、数据一致性和生产冒烟证据齐全；测试账号和测试数据状态可追溯。

## 输出物

- `audit-inventory.csv`：全站资产与接口映射
- `audit-role-matrix.csv`：角色、页面、接口和权限矩阵
- `audit-cases/`：按批次拆分的用例
- `audit-evidence/`：请求、响应、截图、日志和数据库快照
- `audit-findings.md`：缺陷、严重级别、复现和修复状态
- `audit-release-report.md`：最终通过结论和遗留风险
