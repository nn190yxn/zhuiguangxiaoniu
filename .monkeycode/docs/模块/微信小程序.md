# 微信小程序模块

`real_sync/mini-program/` 是当前功能较完整的原生微信小程序工程，覆盖登录、学习、考试、制度、知识库、AI 演练、通关、通知、工作量、积分、排行、商城、每日签到、绑定、提醒和个人中心。`business-domain-matrix.json` 进一步固定首页、认证、档案、积分、排行、商城、打卡、知识、证书和反馈十个业务域的页面、入口、稳定 API、状态与恢复动作。

## 请求模式

页面通过 `utils/api.js` 调用 `/api` 接口，业务页面不直接调用 `wx.request` 或 `wx.uploadFile`。请求层附加 Bearer Token、请求 ID、幂等键和状态版本，并将 HTTP、业务、网络、超时、冲突与上传协议错误转换为稳定错误对象。本地无 Token 的受保护操作直接进入 `reauthentication`，网络调用数保持为零；访问令牌到期或 HTTP/业务码 401 时共享一次设备会话刷新，并为普通请求和文件上传各重放一次。刷新失败统一写入 `reauthentication` 状态并返回登录页。

普通请求默认超时 15 秒，上传默认超时 60 秒。上传层使用 `wx.getFileInfo` 计算 SHA-256 摘要并通过 `file_sha256` 提交，同时保留上传进度；调用方可传入已有 `uploadDigest`。登录、微信登录和身份绑定使用 `auth=false`，保证匿名认证请求独立于旧设备会话。

登录请求使用 `client_type=mini_program` 和当前 `identity_provider`。已绑定微信或企业微信的员工获得绑定员工、身份摘要、设备、客户端和会话版本的短期设备会话；`utils/auth.js` 将访问 Token 继续双写到 `token` 与 `jwt_token`，并在独立键中保存轮换刷新凭据、会话 ID 和版本。密码登录后的待绑定流程保持历史 JWT 兼容，绑定成功后升级为设备会话。退出立即清理本地授权数据，并调用 `/api/auth/mini-program-session.php?action=logout` 撤销服务端会话族。

## 导航与能力版本

`app.json` 的 `tabBar.list` 是 Tab 页面权威清单。业务入口通过 `utils/navigation.js` 导航：Tab 页面使用 `switchTab`，普通页面使用 `navigateTo`，流程替换和登录完成分别使用 `redirectTo` 与 `reLaunch`。Tab 页面查询参数先写入页面专属临时存储，目标页面消费后立即清理；外域和非法页面目标返回“页面暂不可用”。

启动时匿名读取 `/api/platform/capabilities.php`。`utils/capabilities.js` 只启用服务端显式声明 `enabled=true` 且当前小程序版本满足 `minimum_client_version` 的功能；能力响应异常或字段缺失时只保留认证、工作量和个人资料核心入口。提醒授权属于可恢复增强能力，授权拒绝、封禁或状态接口异常时用户可选择“稍后设置”进入首页。

## 十域页面状态

`app.json` 当前登记 32 个页面。首页通过 `goPoints` 进入 `pages/points/index`，该页聚合 `/points/index.php`、`/points/ranking.php`、`/points/exchange.php` 和 `/points/checkin.php`。排行使用服务端 `user_points` 权威数据，按累计积分和用户 ID 稳定排序，并返回当前用户排名。

`utils/view-state.js` 将读取过程统一为 `loading`、`empty`、`ready`、`error`、`offline` 和 `conflict`，将写入过程统一为 `idle`、`submitting`、`success`、`error`、`offline` 和 `conflict`。网络与超时错误进入 `offline`，409 进入 `conflict`，错误状态携带明确恢复动作。商城兑换和每日签到保留待处理操作及首次生成的 `idempotencyKey`，重试复用该操作键；网络恢复后积分页自动重试离线读取。

`scripts/miniprogram_business_domain_matrix.test.mjs` 验证十域顺序、页面注册、入口、稳定 API、读取状态以及写域恢复语义；`scripts/miniprogram_view_state.test.mjs` 验证错误分类；`scripts/miniprogram_points_api_contract.test.mjs` 验证积分排行与写入契约。

## 开发检查

1. 新页面同步注册到 `app.json`。
2. API 请求和上传复用统一请求层，业务页面禁止直接调用原生网络 API。
3. 登录态兼容 `token` 与 `jwt_token` 历史键。
4. 受认证请求与上传依赖统一刷新队列，业务页面不直接读取刷新凭据。
5. 写请求传入幂等键和状态版本，上传携带 SHA-256 摘要。
6. 上传、超时和业务错误提供可重试反馈。
7. 固定和动态页面入口复用统一导航工具，Tab 清单与 `app.json` 保持一致。
8. 新增功能在能力端点登记最低客户端版本，并验证端点异常时的保守降级。
9. 运行 `node scripts/check_miniprogram_contracts.mjs`、十域状态测试和 `node scripts/platform_preflight.mjs`，确认静态契约与页面状态无阻断项。
10. 在微信开发者工具和真机分别验证。
11. 提审前核对 request、uploadFile、downloadFile 和 web-view 域名。

仓库中的 `real_sync/mobile/` 包含另一套历史移动端及小程序相关源码。发布改动前依据实际微信工程确认目标目录。
