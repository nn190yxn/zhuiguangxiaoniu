# 手机 H5 PWA 壳层需求文档

Feature Name: mobile-pwa-shell
Updated: 2026-07-29

## 简介

追光小牛员工端以手机浏览器作为近期移动入口。员工可以将 H5 应用安装到手机桌面，从桌面图标以独立应用窗口进入工作量、销售演练、学习和个人中心。

## 术语

- **PWA**：通过浏览器安装到手机桌面的 Web 应用。
- **独立窗口**：隐藏浏览器地址栏后以应用界面显示的运行模式。
- **安装引导**：向员工说明 Android 安装操作或 iPhone“添加到主屏幕”操作的界面。
- **应用外壳**：离线可打开的页面框架、静态资源与导航。

## 需求

### 需求 1：可安装入口

**用户故事：** 作为员工，我希望把追光小牛员工端放到手机桌面，以便像打开普通应用一样进入日常工作。

#### 验收标准

1. 当员工通过 HTTPS 打开任一核心手机 H5 页面时，系统应提供符合 Web App Manifest 规范的应用描述。
2. 当支持浏览器安装事件时，系统应提供“安装到桌面”操作并触发浏览器安装流程。
3. 当 iPhone 浏览器打开核心手机 H5 页面时，系统应展示“分享后添加到主屏幕”的安装说明。
4. 当员工从桌面图标进入应用时，系统应以独立窗口模式打开 `/mobile/mine.html`。

### 需求 2：统一手机应用体验

**用户故事：** 作为员工，我希望在工作量、演练、学习和个人中心之间保持一致的应用体验，以便快速完成每日任务。

#### 验收标准

1. 当员工访问个人中心、工作量、演练或学习页时，系统应加载相同的应用名称、主题色、桌面图标和安全区域设置。
2. 当应用以独立窗口运行时，系统应为页面根节点提供独立运行状态标识，供页面布局使用。
3. 当员工关闭安装引导时，系统应在七天内保留关闭状态。

### 需求 3：网络与更新提示

**用户故事：** 作为员工，我希望在网络变化和应用更新时获得明确提示，以便避免误以为数据已经提交或页面已经更新。

#### 验收标准

1. 当设备离线时，系统应展示网络不可用提示，并允许已缓存的应用外壳继续打开。
2. 当网络恢复时，系统应移除离线提示并触发页面的在线事件。
3. 当 Service Worker 检测到新应用外壳时，系统应展示刷新提示。
4. 当 API 请求失败时，系统应继续使用既有 ApiClient 的受控错误处理与登录态策略。

### 需求 4：缓存边界

**用户故事：** 作为系统管理员，我希望 PWA 仅缓存应用外壳和静态资源，以便员工数据始终来自受认证的服务端接口。

#### 验收标准

1. 系统应缓存核心手机 H5 页面、公共脚本、清单和图标资源。
2. 系统应为 `/api/` 请求保留网络访问路径。
3. 当离线请求未缓存页面时，系统应返回个人中心应用外壳。
4. 当新应用外壳激活时，系统应清理旧版本应用外壳缓存。
