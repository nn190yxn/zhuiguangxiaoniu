# UI 开发方案

Updated: 2026-07-24

## 1. 目标

本方案在现有前端视觉基础上完成员工移动端、员工与组织管理后台和工作量统计后台的体验重构。视觉继续使用品牌橙、深棕文字、暖灰背景、白色卡片、柔和阴影、圆角和现有状态色，页面结构和交互反馈统一到可复用规则。

优先级：

1. 强化员工 H5 与小程序工作量填报流程。
2. 建立可直接操作的员工通讯录和组织管理页面。
3. 统一管理后台筛选、状态、抽屉、表格和反馈组件。
4. 补齐响应式、键盘操作、无障碍语义和自动化测试接口。

## 2. 视觉连续性

### 2.1 保留的视觉语言

| 设计元素 | 现有基线 | 使用规则 |
| --- | --- | --- |
| 品牌色 | `#ff6b35` | 主按钮、当前导航、关键进度和主操作 |
| 主文字 | `#1f1a17` | 标题、正文和关键数据 |
| 次级文字 | `#6b625c` | 说明、辅助字段和时间信息 |
| 页面背景 | `#f5f1ea` 至 `#faf7f2` | 管理后台和移动端暖灰背景 |
| 卡片 | 白色、浅边框、低强度阴影 | 内容分组、摘要和表单区域 |
| Hero | 橙色或深棕渐变 | 页面身份、今日状态和管理摘要 |
| 圆角 | 12px、16px、20px | 输入、按钮、卡片和抽屉 |

### 2.2 状态颜色

| 状态 | 颜色语义 | 示例 |
| --- | --- | --- |
| 成功 | 绿色 | 已提交、已启用、审核通过 |
| 进行中 | 蓝色 | 上传中、处理中、同步中 |
| 提醒 | 橙色 | 草稿、待补凭证、待确认 |
| 风险 | 红色 | 锁定缺交、输入错误、停用、离职 |
| 中性 | 暖灰 | 未开始、无数据、已归档 |

颜色与文字标签同时出现，状态识别不依赖单一颜色。

## 3. 员工移动端方案

### 3.1 页面信息顺序

H5 `mobile/workload-v2.html` 与小程序 `mini-program/pages/workload/index.*` 使用统一内容顺序：

1. 今日身份卡：姓名、门店、岗位、日期和截止时间。
2. 日报状态条：未开始、草稿、已提交、公休日或锁定。
3. 完成进度：已填写正数项目数、最低要求、待补凭证数。
4. 项目表单：按分类分组，突出必填、单位、数值和凭证状态。
5. 备注与凭证：说明自动保存草稿的真实行为。
6. 固定操作栏：保存草稿、提交日报和处理状态。

普通员工的姓名、门店和岗位使用只读卡片。具备跨门店或多岗位权限的用户使用明确的选择器，并在切换前处理未保存修改。

### 3.2 项目填写

- 每个项目行展示名称、单位、适用状态、数值输入和凭证数量。
- 必填项目使用文字和视觉标记。
- 输入错误显示在对应项目下方，并将焦点移动到首个错误。
- 页面顶部进度随输入实时更新，例如“已完成 3/4 项，另有 1 项待补凭证”。
- 零值、未适用和正数值使用明确状态，避免把空输入隐式解释为零。
- 提交失败保留全部输入和图片状态。

### 3.3 草稿与离页

- 首次修改后展示“尚未保存”。
- 保存成功展示最后保存时间。
- 切换日期、岗位、门店或业务页面时，优先自动保存草稿；保存失败时显示确认框。
- H5 使用应用内确认和浏览器离页提示。
- 小程序在业务返回入口、`onHide` 和 `onUnload` 记录恢复状态。
- 首页和工作量页读取服务端义务，持续展示到期草稿和锁定缺交状态。

### 3.4 凭证上传

- 上传文案统一为“选择图片后会自动保存当前内容为草稿”。
- 上传前展示数量、格式和大小限制。
- 上传中展示单图进度、取消状态和整体数量。
- 上传失败保留待重试图片，并提供明确重试按钮。
- 删除凭证使用二次确认，完成后立即更新项目凭证缺口。
- H5 与小程序统一 5MB 限制、数量上限、超时和错误文案。

### 3.5 固定操作栏

- 操作栏适配 iOS 和 Android 底部安全区。
- 保存和提交期间按钮进入 loading 和 disabled 状态。
- 连续点击只产生一个有效请求。
- 锁定、公休日和已提交状态显示对应主操作，例如“查看已提交日报”或“联系管理员处理”。
- 成功反馈展示提交时间、后台可见状态和返回工作台入口。

## 4. 员工与组织管理后台

### 4.1 页面导航

`admin/staffs.html` 保留现有顶部导航和 Hero，内容区增加页内标签：

- 员工一览
- 组织架构
- 门店设置
- 岗位设置
- 批量导入
- 数据健康

当前标签使用品牌橙胶囊样式。移动宽度下标签横向滚动，保持主要操作可见。

### 4.2 员工一览

顶部摘要突出在职、待入职、停用、离职和数据异常数量。筛选区支持关键词、门店、岗位、系统角色、人员状态和入职时间。

桌面端使用表格，展示姓名与工号、门店、主岗位、系统角色、手机号、账号状态和操作。窄屏使用员工卡片，保留相同信息优先级。

行操作收口为“查看详情”，离职、恢复、重置密码和清理放入详情抽屉，降低误触风险。

### 4.3 新增员工抽屉

抽屉按三步组织：

1. 基础资料：姓名、手机号、工号和入职日期。
2. 组织与权限：门店、主岗位、兼岗和系统角色。
3. 账号确认：登录账号、管理员设置的初始密码和创建摘要。

每一步显示已完成状态。提交前展示脱敏确认摘要，创建期间锁定重复操作，成功后直接打开新员工详情。

### 4.4 员工详情

详情抽屉包含：

- 基础资料与账号状态。
- 当前门店、主岗位、兼岗和系统角色。
- 任职历史时间线。
- 工作量、学习、设备和登录摘要。
- 微信与企业微信绑定状态。
- 操作审计时间线。

高风险操作使用独立风险区。离职归档需要日期、原因和确认；误建清理先展示业务关联检查结果；恢复需要重新选择有效门店、岗位和角色。

### 4.5 组织架构与基础设置

组织架构支持树形和列表两种视图。树形按总部、门店、岗位和员工展开，列表适合筛选与批量核对。

门店和岗位设置使用同一列表模式：名称、编码、负责人或适用角色、引用人数、排序、状态和操作。停用前展示当前引用及需要处理的员工。

### 4.6 批量导入与数据健康

导入页面提供模板下载、拖放上传、字段映射、预检查、逐行结果和失败行重试。结果使用成功、提醒和错误三种状态。

数据健康页面展示重复工号、重复手机号、重复账号、无效门店、无效岗位、角色不一致和孤立账号。每项问题提供影响范围、修复入口和审计结果。

## 5. 工作量管理后台延续

`admin/workload.html` 继续使用现有暖色管理后台风格，统一以下组件：

- 组合筛选器和已生效条件摘要。
- 完成率、缺交和异常门店三个主 KPI。
- 次级指标折叠区。
- 局部骨架屏、顶部错误条和重试按钮。
- 可键盘操作的表格行、员工抽屉和图片预览。
- 趋势图文字摘要与同数据表格。

员工详情和组织任职信息从员工管理服务读取，统计历史继续以业务日期快照为准。

## 6. 共享组件与状态

优先沉淀以下可复用模式：

- `StatusPill`：文本、颜色和图形状态。
- `AsyncButton`：loading、disabled、防重和结果反馈。
- `InlineFieldError`：字段错误与焦点定位。
- `EmptyState`：无数据说明和下一步操作。
- `ErrorState`：错误摘要、追踪 ID 和重试。
- `Skeleton`：列表、卡片和详情加载占位。
- `ConfirmDialog`：普通确认与高风险确认。
- `Drawer`：焦点管理、Escape 关闭和背景滚动锁定。
- `FilterBar`：组合筛选、清空和条件摘要。

现有项目以原生 HTML、JavaScript、WXML 和 WXSS 为主，共享规则通过 CSS 变量、公共样式类和小型工具函数实现，控制改造范围。

## 7. 响应式与无障碍

- 桌面宽度使用双栏、表格和右侧抽屉。
- 平板宽度将筛选器改为两列，详情抽屉占主要宽度。
- 手机宽度使用单列卡片、横向标签和固定底部操作。
- 所有交互控件提供可见焦点、明确标签和至少 44px 触控区域。
- 抽屉和对话框设置语义、焦点进入、焦点返回和 Escape 关闭。
- 图片提供用途说明和加载失败占位。
- Canvas 趋势图提供文字摘要或同数据表格。
- 动效控制在 150ms 至 240ms，并遵循减少动态效果偏好。

## 9. 自动化验证

- H5 与小程序对同一模板、员工和日报 Fixture 展示一致规则、状态和错误。
- 保存、上传和提交重复点击只产生一次有效请求。
- 普通员工身份字段保持只读，授权用户能够切换合法范围。
- 输入错误定位到对应项目，修正后状态实时清除。
- 草稿离页、恢复、锁定和公休日状态完整覆盖。
- 员工一览筛选、分页、窄屏卡片和详情抽屉使用相同数据。
- 新增员工三步表单覆盖成功、重复手机号、无效门店、无效岗位和弱密码。
- 离职、恢复和误建清理展示服务端资格检查结果。
- 抽屉、对话框、表格行和图片预览支持键盘操作及焦点恢复。
- 加载、空数据、错误、超时和成功状态均有可测试 DOM 或小程序节点标识。
