| 能力 | 目标 |

## 4. 目标统计体系

统计底座采用以下最细粒度：

```text
业务日期 + 门店 + 员工 + 岗位 + 工作量项目
```

核心交叉分析：

| 分析 | 主要结果 |
| --- | --- |
| 门店 × 项目 | 总量、人均、有效值、覆盖率、环比和排名 |
| 项目 × 员工 | 参与员工、个人值、均值、环比和排名 |
| 门店 × 员工 | 日报完成率、项目组合和每应交人日效率 |
| 门店 × 项目 × 员工 | 最细下钻和全维度导出 |
| 时间 × 门店 | 日、业务周、月和季度趋势 |
| 时间 × 项目 | 选取率、有效值和覆盖趋势 |
| 时间 × 员工 | 个人趋势、连续变化和异常波动 |

每个统计单元同时返回：

- 原始总量。
- 待审核量。
- 审核有效总量。
- 应交人日。
- 已提交人日。
- 每应交人日均值。
- 参与员工人均值。
- 项目选取率。
- 员工覆盖率。
- 门店覆盖率。
- 样本量。
- 统计口径版本。

## 5. 对比与环比

| 当前周期 | 对比周期 |
| --- | --- |
| 日 | 上一个营业日 |
| 业务周 | 上一个周二至周日 |
| 月累计 | 上月相同营业日数量 |
| 完整月 | 上一个完整月并排除周一 |
| 季度 | 上一个完整季度并排除周一 |
| 自定义周期 | 前一个等长营业日周期 |

所有对比同时展示本期、上期、变化量、变化率、营业日数、应交人日和样本量。上期为零时使用新增、持平和下降到零状态。

参考基准包括：

- 本人或本门店上期。
- 过去四期自身均值。
- 门店同岗位均值。
- 全部门店同岗位均值。
- 前百分之二十五参考值。
- 门店总排名。
- 员工门店内排名。
- 员工全部门店同岗位排名。

## 9. 提醒、预警与建议

第一期使用确定性规则：

- 草稿临期提醒。
- 日报缺交提醒。
- 24:00 锁定缺交预警。
- 门店完成率黄色和红色预警。
- 项目低选取与低覆盖提示。
- 审核 24 小时和 48 小时积压预警。
- 员工连续两个周期下降提示。
- 长期恰好填写四个正数项目的数据质量提示。
- 相比过去四期均值的异常波动提示。

每条事件保存规则、周期、阈值、分子、分母、样本量、当前值、处理人、意见和状态。

## 12. 部署与回滚顺序

每批采用固定流程：

```text
只读核验 -> 独立备份 -> 增量迁移 -> 单项修改 -> 自动测试 -> 数据对账 -> 页面回归 -> 小范围发布 -> 发布后复查
```

每批保持独立备份点、数据库迁移记录、文件校验值和回滚入口。新统计接口采用双算方式与旧口径对账，确认差异后切换页面读取。

## 13. 完成标准

- 周一应交数为零。
- 周二至周日在职适用员工均有唯一日报义务。
- 次日 00:00 后员工日报保持锁定。
- 原始值、待审核值和有效值全链路一致。
- 门店、项目、员工和时间交叉表可以下钻到最细事实记录。
- 页面、接口和导出聚合结果一致。
- 环比周期包含相同营业日数量。
- 权限矩阵覆盖查询、排名、下钻、导出和配置。
- 小程序静态路由错误清零并产生真实 `mini_program` 日报。
- 企业微信运行分支进入可恢复停用状态。
- 总部运营和系统管理员可以直接新增、编辑、离职、恢复和重置员工账号。
- 员工门店与岗位变更保留带生效日期的任职历史。
- 有业务数据的员工完成离职归档，无业务数据误建员工通过校验后可受控清理。
- H5 与小程序提交规则、身份信息、填写进度和错误反馈保持一致。
- 全部必做测试通过。
