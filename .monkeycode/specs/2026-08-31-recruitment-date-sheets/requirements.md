# 招聘简历按日期分表导出需求

## 简介

招聘人员需要把指定日期范围内收到的简历导出到同一个 Excel 文件中，并以“简历收到日期”为一级分组。每个日期工作表包含当天全部简历，按照岗位配置顺序排列，便于线下反馈、历史追踪和后续批次补充。

## 术语

- **简历收到日期**：招聘简历文档的 `recruitment_resume_documents.created_at` 按系统业务时区转换后的日期。
- **日期工作表**：以 `YYYY-MM-DD` 命名、承载同一简历收到日期全部记录的 Excel 工作表。
- **当天全部简历**：指定日期内已归类候选人、待确认岗位简历和处理失败简历的文档集合。
- **岗位配置顺序**：`organization_positions.sort_order` 升序；排序值相同时使用岗位 ID 升序。
- **未归类简历**：尚未形成有效招聘申请记录的简历文档，包括待确认岗位和处理失败记录。

## 需求

### 需求 1：按简历收到日期生成工作表

**用户故事：** 作为招聘人员，我希望每个收到日期都有独立工作表，以便按日期维护线下反馈记录。

#### 验收标准

1. 当导出结果覆盖一个或多个简历收到日期时，系统应为每个有记录的日期生成一个日期工作表。
2. 当日期工作表生成时，系统应使用 `YYYY-MM-DD` 作为工作表名称。
3. 当单个日期没有符合导出范围的简历时，系统应跳过该日期工作表。
4. 当工作表名称与 Excel 名称限制冲突时，系统应生成唯一且可识别的安全名称。

### 需求 2：日期工作表包含当天全部简历

**用户故事：** 作为招聘人员，我希望日期工作表包含当天收到的全部简历，以便线下反馈覆盖完整输入。

#### 验收标准

1. 当日期工作表生成时，系统应包含当天的 A、B、C 级候选人记录。
2. 当日期工作表生成时，系统应包含当天的待确认岗位简历记录。
3. 当日期工作表生成时，系统应包含当天的处理失败简历记录。
4. 当简历缺少候选人、岗位或评分数据时，系统应保留该简历行并对缺失字段写入空值或可读状态。
5. 当日期工作表生成时，系统应确保每个源简历文档在当天工作表中最多出现一条记录。

### 需求 3：按岗位配置顺序排列

**用户故事：** 作为招聘人员，我希望同一天的简历按岗位配置顺序排列，以便按照线下招聘工作顺序处理。

#### 验收标准

1. 当日期工作表包含多个岗位时，系统应按 `organization_positions.sort_order` 升序排列岗位。
2. 当多个岗位具有相同配置顺序时，系统应按岗位 ID 升序排列岗位。
3. 当同一岗位包含多份简历时，系统应按简历收到时间升序排列。
4. 当同一岗位的简历收到时间相同时，系统应按源简历文档 ID 升序排列。
5. 当记录未归类到岗位时，系统应将记录排列在所有已归类岗位之后。

### 需求 4：保留现有导出能力

**用户故事：** 作为招聘人员，我希望继续使用现有导出筛选、权限和字段，以便现有工作流程保持连续。

#### 验收标准

1. 当招聘人员选择全部批次或当前批次时，系统应继续执行现有招聘权限范围校验。
2. 当招聘人员设置日期起止条件时，系统应按简历收到日期包含起始日和结束日筛选记录。
3. 当招聘人员设置等级条件时，系统应继续应用等级筛选。
4. 当生成日期工作表时，系统应继续执行现有联系信息权限和公式安全处理。
5. 当生成导出任务记录时，系统应保存实际筛选条件、行数和字段排序版本。

### 需求 5：工作簿可追溯且可读取

**用户故事：** 作为招聘人员，我希望工作簿保留总览和日期信息，以便核对导出范围并继续离线更新。

#### 验收标准

1. 当导出成功时，系统应保留总览工作表并包含所有日期工作表中的记录。
2. 当导出成功时，系统应保留现有按岗位查看能力，或提供等价的稳定岗位汇总工作表。
3. 当工作簿被标准 XLSX 解压工具读取时，系统应为每个声明的工作表提供对应关系和 XML 文件。
4. 当工作簿包含以公式起始字符开头的文本时，系统应继续将文本转换为安全文本。
5. 当没有任何符合条件的简历时，系统应生成包含表头的可读取工作簿，并返回行数为零。

## 范围外

- 修改简历处理、岗位分类、评分或联系状态业务逻辑。
- 自动把历史导出文件追加写回服务器上的既有 Excel 文件。
- 修改招聘人员的权限模型和联系信息脱敏规则。
