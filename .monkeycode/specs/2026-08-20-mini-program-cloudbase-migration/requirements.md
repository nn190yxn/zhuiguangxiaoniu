# 微信小程序腾讯云开发全量迁移需求文档

Feature Name: `mini-program-cloudbase-migration`
Updated: 2026-08-21
Status: Confirmed

## 1. 简介

本规格定义追光小牛原生微信小程序向腾讯云开发迁移的业务需求。迁移覆盖 `app.json` 已登记的 32 个页面及其认证、数据请求、文件、音频、订阅消息和错误恢复能力。迁移后，小程序使用微信云开发能力访问业务服务，现有 PHP、WordPress 身份体系和 MySQL 继续保存与解释权威业务数据，官网、H5、管理后台和小程序共享同一套业务事实。

本次迁移采用全功能范围和一次生产切换目标。开发与验证按可回滚批次推进，生产切换时保留受控传输开关和旧链路观察窗口。

## 2. 术语

- **小程序**：位于 `real_sync/mini-program/` 的原生微信小程序，共登记 32 个页面。
- **云开发入口**：由微信云开发提供、供小程序通过 `wx.cloud` 调用的云函数或云托管服务。
- **现有业务后端**：部署于现网的 PHP API、WordPress 身份数据、MySQL 业务数据、Worker 和文件服务。
- **权威数据源**：对业务事实拥有最终写入和解释权的现有 PHP/MySQL 数据模型。
- **云函数网关**：接收小程序结构化请求并按固定路由转发到现有 PHP API 的云函数。
- **媒体适配服务**：负责云存储文件、现有文件服务和媒体业务记录之间受控传输的云托管服务。
- **设备会话**：绑定员工、微信身份、设备、客户端和会话版本的短期访问会话。
- **传输模式**：客户端使用的请求路径，包含 `cloud`、`direct` 和 `shadow` 三种受控模式。
- **影子核对**：用户读取云路径结果，同时由受控后台抽样读取旧路径并比较脱敏业务结果。
- **媒体资产键**：连接 MySQL 业务记录、历史文件和云存储文件的稳定标识。
- **完整迁移范围**：首页、认证、档案、制度、通知、学习、知识、考试、通关、演练、积分、工作量、提醒和个人中心。

## 3. 需求

### 需求 1：全功能迁移范围

**用户故事：** 作为员工，我希望现有小程序功能在云开发版本中完整可用，以便继续完成日常工作。

#### 验收标准

1. WHEN 迁移范围建立，小程序 SHALL 将 `app.json` 登记的 32 个页面关联到业务域、入口、API、媒体字段和微信原生能力。
2. WHEN 云开发版本进入验收，小程序 SHALL 提供首页、认证、档案、制度、通知、学习、知识、考试、通关、演练、积分、工作量、提醒和个人中心现有功能。
3. WHEN 页面调用业务能力，小程序 SHALL 通过统一客户端请求层访问对应云开发入口。
4. WHEN 页面需要录音、相册、相机、文件选择或订阅消息，小程序 SHALL 通过统一客户端适配器调用对应微信能力。
5. WHEN 服务端能力版本低于页面最低版本，小程序 SHALL 使用能力响应隐藏对应入口并展示稳定恢复说明。

### 需求 2：单一权威业务数据

**用户故事：** 作为业务负责人，我希望官网和小程序共用现有数据，以便所有端显示一致业务结果。

#### 验收标准

1. WHEN 小程序读取或写入业务事实，云开发入口 SHALL 将请求交给现有 PHP 业务服务和 MySQL 权威数据源处理。
2. WHEN 官网、H5、管理后台和小程序访问相同业务对象，系统 SHALL 返回同一稳定对象标识、业务状态和数据范围。
3. WHEN 云开发需要保存运行数据，系统 SHALL 将路由配置、短期任务状态和媒体映射与权威业务事实分开管理。
4. WHEN 小程序完成业务写入，系统 SHALL 从现有 PHP 业务服务返回提交后的权威状态。
5. IF 云开发入口与现有业务后端之间发生超时，系统 SHALL 保持 MySQL 已提交事务结果并向客户端返回可核对的请求 ID 和恢复动作。

### 需求 3：云开发统一请求入口

**用户故事：** 作为发布负责人，我希望小程序业务请求通过云开发完成，以便降低小程序业务域名配置依赖。

#### 验收标准

1. WHEN 小程序发起普通 JSON 请求，小程序 SHALL 使用 `wx.cloud.callFunction` 调用云函数网关。
2. WHEN 云函数网关接收请求，云函数网关 SHALL 按固定方法和路径白名单选择现有 PHP API。
3. WHEN 云函数网关转发请求，云函数网关 SHALL 传播 `Authorization`、`X-Request-ID`、`Idempotency-Key` 和状态版本字段。
4. WHEN 现有 PHP API 返回结果，云函数网关 SHALL 保持 HTTP 语义、业务码、消息、数据、请求 ID 和冲突恢复数据。
5. IF 客户端请求的路径、方法或参数类型超出路由登记，云函数网关 SHALL 返回稳定输入错误并记录脱敏拒绝事件。
6. WHEN 云开发入口进入发布检查，发布门禁 SHALL 验证业务请求、上传、下载和媒体播放链路均具备云开发路径。

### 需求 4：双登录与账号绑定

**用户故事：** 作为员工，我希望使用微信身份或账号密码进入小程序，以便兼顾便捷登录和历史账号使用。

#### 验收标准

1. WHEN 已绑定员工提交微信登录凭据，系统 SHALL 通过现有员工映射签发小程序设备会话。
2. WHEN 员工提交账号和密码，系统 SHALL 通过现有 WordPress 账号与员工档案完成验证并签发小程序设备会话。
3. WHEN 密码登录员工需要绑定微信身份，系统 SHALL 签发短期、单次使用且绑定当前员工的绑定票据。
4. WHEN 绑定页面提交绑定票据和微信登录凭据，系统 SHALL 在现有 PHP 事务中更新员工微信身份并递增会话版本。
5. WHEN 访问凭据到期，客户端请求层 SHALL 通过单飞刷新流程轮换刷新凭据并重放每个原请求一次。
6. IF 系统检测到已轮换刷新凭据再次使用，系统 SHALL 撤销对应会话族并要求重新认证。
7. WHEN 员工退出、停用、改密或身份重新绑定，系统 SHALL 清理客户端凭据并按现有会话版本规则终止旧会话。

### 需求 5：权限与接口契约保持一致

**用户故事：** 作为员工和管理人员，我希望迁移前后拥有相同权限和数据范围，以便业务规则保持稳定。

#### 验收标准

1. WHEN 受保护请求进入现有业务后端，系统 SHALL 从统一员工上下文解析用户、员工、角色、门店、岗位、任职和会话版本。
2. WHEN 小程序与 H5 访问相同业务，系统 SHALL 应用相同具名权限、门店范围和员工本人范围。
3. WHEN 写请求可能重复到达，系统 SHALL 使用原始 `Idempotency-Key`、请求摘要和业务唯一约束返回单一业务结果。
4. IF 客户端状态版本落后于权威版本，系统 SHALL 返回冲突码、当前版本、权威状态和恢复动作。
5. WHEN 云路径响应进入客户端，小程序 SHALL 继续使用现有视图状态表达读取、提交、成功、离线、冲突和恢复动作。

### 需求 6：图片、文件和音频迁移

**用户故事：** 作为员工，我希望工作量凭证、课程媒体和演练录音通过云开发正常使用，以便完成包含媒体的业务流程。

#### 验收标准

1. WHEN 用户选择新图片或录音文件，小程序 SHALL 将文件上传到云存储并获得云文件标识。
2. WHEN 业务后端需要接收新媒体，媒体适配服务 SHALL 校验员工权限、实际类型、大小、SHA-256、业务用途和留存策略后执行受控传输。
3. WHEN PHP 完成媒体业务登记，系统 SHALL 保存稳定媒体资产键和对应业务对象关系。
4. WHEN API 返回图片或音频字段，云开发入口 SHALL 返回小程序可读取的云文件标识或受控临时访问结果。
5. WHEN 小程序首次访问历史媒体，媒体适配服务 SHALL 按需复制历史文件到云存储并保存幂等映射。
6. WHEN 演练上传音频，系统 SHALL 保持实例归属、分片编号、分片数量、摘要、状态版本和幂等契约。
7. IF 媒体传输中断，系统 SHALL 保留可恢复任务状态并允许客户端使用同一业务标识继续传输。

### 需求 7：微信原生能力与提醒

**用户故事：** 作为员工，我希望微信授权、提醒和录音体验在迁移后保持可用，以便及时处理工作任务。

#### 验收标准

1. WHEN 页面需要微信身份，小程序 SHALL 在客户端调用 `wx.login` 并将短期凭据提交给认证云入口。
2. WHEN 员工申请订阅提醒，小程序 SHALL 在客户端调用 `wx.requestSubscribeMessage` 并将授权结果写入现有提醒业务记录。
3. WHEN 用户稍后处理提醒授权，小程序 SHALL 保留提醒设置入口并允许再次申请。
4. WHEN 演练页面需要录音，小程序 SHALL 使用微信录音管理器采集文件并通过统一媒体流程提交。
5. WHEN 页面播放云端音频，小程序 SHALL 先获取可播放的本地临时路径再交给音频组件。

### 需求 8：可靠性、错误恢复与可观测性

**用户故事：** 作为运维负责人，我希望迁移后的请求可追踪、可恢复，以便快速定位云端和现有后端之间的问题。

#### 验收标准

1. WHEN 请求进入小程序请求层，小程序 SHALL 生成或传播请求 ID 到云开发入口和现有 PHP API。
2. WHEN 云开发入口调用现有后端，系统 SHALL 记录路由、业务域、耗时、结果分类和请求 ID。
3. WHEN 日志涉及密码、Token、OpenID、录音、图片或员工档案，系统 SHALL 使用隐藏、摘要或字段掩码保存日志信息。
4. IF 云函数达到超时阈值，系统 SHALL 返回稳定超时分类和可重试标记。
5. IF 云托管媒体任务达到自动重试上限，系统 SHALL 保存恢复状态和可查询任务标识。
6. WHEN 云入口健康检查运行，系统 SHALL 分别报告云函数、云托管、现有 PHP API、MySQL 和媒体存储依赖状态。

### 需求 9：传输切换与回滚

**用户故事：** 作为发布负责人，我希望迁移具备受控切换和回滚路径，以便在异常时恢复现有小程序链路。

#### 验收标准

1. WHEN 迁移开发开始，小程序 SHALL 支持 `direct`、`cloud` 和 `shadow` 三种受控传输模式。
2. WHILE 影子核对运行，系统 SHALL 向用户返回云路径结果并保存脱敏差异结果。
3. WHEN 生产切换获得批准，小程序 SHALL 将默认传输模式切换为 `cloud` 并保留配置化回滚入口。
4. IF 观察窗口达到错误率、延迟、数据差异或核心旅程停止阈值，发布流程 SHALL 停止后续步骤并恢复上一批准传输模式。
5. WHEN 传输模式回滚，系统 SHALL 保留迁移期间已写入的权威 MySQL 数据和可兼容媒体映射。
6. WHEN 观察窗口结束，发布证据 SHALL 保存版本、配置、契约核对、业务核对、异常记录和回滚状态。

### 需求 10：迁移前业务缺陷收口

**用户故事：** 作为产品负责人，我希望已发现的关键业务偏差在云路径验收前得到修正，以便迁移验证基于正确行为。

#### 验收标准

1. WHEN 用户确认制度通知，系统 SHALL 使用通知记录标识执行确认并保存对应制度关系。
2. WHEN 学习页面打开通关阶段，小程序 SHALL 使用通关页面约定的统一阶段参数名。
3. WHEN 小程序保存协议接受状态，登录页和应用启动流程 SHALL 使用同一状态键和版本。
4. WHEN 密码登录员工进入微信绑定流程，小程序 SHALL 使用绑定票据替代跨页面保存账号密码。
5. WHEN 知识详情包含示范音频，小程序 SHALL 提供实际播放、暂停、错误和完成状态。
6. WHEN 系统分配考试，小程序 SHALL 通过具备幂等语义的写请求创建试卷分配结果。

### 需求 11：验证与发布门禁

**用户故事：** 作为发布负责人，我希望获得完整自动验证证据，以便确认 32 个页面迁移结果。

#### 验收标准

1. WHEN 云函数网关进入集成阶段，自动测试 SHALL 覆盖路由白名单、请求头传播、响应契约、超时、401 刷新和 409 冲突。
2. WHEN 认证改造完成，自动测试 SHALL 覆盖密码登录、微信登录、绑定票据、刷新轮换、凭据复用、退出和会话版本失效。
3. WHEN 媒体迁移完成，自动测试 SHALL 覆盖类型、大小边界、摘要差异、重复上传、历史媒体镜像和云文件失效。
4. WHEN 演练迁移完成，自动测试 SHALL 覆盖幂等重试、状态冲突、分片缺失、重复分片和最终提交恢复。
5. WHEN 客户端迁移完成，静态检查 SHALL 验证 32 个页面注册、导航、统一请求层、统一媒体层和云环境配置。
6. WHEN 生产切换进入批准阶段，真机验收 SHALL 覆盖 iOS 与 Android 上的双登录、首页、制度、通知、学习、知识、考试、通关、积分、工作量、提醒、个人中心和演练主流程。
7. WHEN 云路径与旧路径接收相同只读输入，契约核对 SHALL 比较 HTTP 语义、业务码、字段、权限范围和权威业务值。
8. IF 任一核心流程、权限边界、数据核对或媒体链路存在阻断结果，发布门禁 SHALL 将迁移状态保持为待处理。

## 4. 范围边界

本次范围包含：

- 原生小程序 32 个页面的云开发传输迁移。
- 现有 PHP API 的云网关适配与必要契约修正。
- 微信登录、账号密码登录、微信绑定、设备会话和退出。
- 工作量图片、课程与知识媒体、积分图片、头像和演练音频。
- 云函数、云存储、云托管媒体适配、配置、日志、测试和回滚开关。
- 现有 MySQL 作为权威业务数据源的跨端一致性。

本次边界保留：

- 官网、H5 和管理后台继续通过现有 Web 入口运行。
- 现有 PHP 领域服务、MySQL 业务模型、权限规则、Worker 和 AI 处理继续承担原有职责。
- 腾讯云开发环境 ID、地域、资源规格和生产密钥由受控环境配置提供。
- 微信后台资质审核、生产资源开通和人工发布批准作为外部发布条件管理。
