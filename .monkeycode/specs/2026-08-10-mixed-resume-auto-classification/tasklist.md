# 需求实施计划

- [x] 1. 建立混合批次数据结构与迁移契约
  - 新增混合批次模式、候选岗位快照、文件分类状态和分类版本所需字段与关联表（设计正确性属性 1、2、6）。
  - 支持岗位规则未发布时的暂存状态，并保留规则版本状态快照（需求 3.1、3.2）。
  - 编写迁移幂等、结构检查和回滚计划测试。

- [x] 2. 实现混合批次创建与上传接口
  - 扩展批次创建接口，允许不绑定单一岗位，并默认读取当前账号可见的全部招聘岗位（需求 1.1、3.1）。
  - 保存候选岗位集合快照、授权范围摘要和岗位规则准备状态（需求 3.4、6.1）。
  - 扩展文件上传服务，允许混合批次逐文件入库并保持现有私有文件、哈希和幂等约束（需求 1.2、1.3、5.4）。
  - 为参数、权限、岗位配置和文件校验失败返回稳定错误码与可执行提示（需求 1.4、3.3、5.1、5.3）。
  - 编写批次创建、权限范围、规则未发布暂存、重复请求和逐文件失败测试。

- [x] 3. 实现简历自动分类服务
  - 新增分类服务，组合文件名、结构化字段、关键词和硬性条件证据（需求 2.1、6.2）。
  - 为高置信度结果写入岗位归属，为低置信度、相近结果和无法判断结果写入待确认状态（需求 2.2、2.3、2.4）。
  - 对规则未发布的岗位保留待分类状态，并在规则发布后创建分类任务（需求 3.2）。
  - 保存分类版本、候选排名、置信度、原因码和脱敏审计信息，保证重复处理幂等（需求 4.3、6.2、6.3）。
  - 编写分类阈值、相近候选、无候选、规则暂存和版本保留测试。

- [x] 4. 实现人工确认与重新分类接口
  - 提供待确认和未归类简历查询，并返回候选岗位、证据摘要、原文件名和处理状态（需求 4.1、4.4）。
  - 支持授权人员选择岗位和重新分类，写入操作人、理由、时间及前后版本（需求 4.2、4.3、6.3）。
  - 使用幂等键和分类状态版本防止重复确认和并发覆盖（设计正确性属性 5、6）。
  - 编写权限、并发冲突、重复确认和历史版本测试。

- [x] 5. 改造后台简历上传页面
  - 增加混合岗位批量上传模式，保留现有指定岗位上传模式（需求 1.1、设计 Upload Page）。
  - 展示全部候选岗位、岗位规则准备状态、暂存提示和逐文件处理结果（需求 3.2、5.3）。
  - 增加待确认队列和人工岗位选择交互，展示分类证据和失败恢复动作（需求 4.1、5.1）。
  - 编写页面契约、状态展示和交互回归测试。

- [x] 6. 检查点：执行招聘模块定向验证
  - 执行新增迁移、服务、接口和页面测试。
  - 执行招聘既有回归、PHP 语法检查和 `git diff --check`。
  - 修复验证发现的问题后再进入文档同步。

- [x] 7. 同步项目文档
  - 更新招聘接口、数据结构、开发验证命令和架构说明。
  - 通过项目文档同步流程刷新 `.monkeycode/docs/` 内容。
  - 执行文档链接和格式检查。

- [x] 8. 最终检查点
  - 确认全部任务完成、测试通过、迁移可重复执行且未影响单岗位批次。
  - 输出变更文件、验证结果和剩余环境门禁。

- [x] 9. 调整岗位明确自动路由
  - 文件名唯一命中最长候选岗位名称时直接归属岗位，不使用分类分数阈值和候选分差作为人工确认条件。
  - 文件名无法形成唯一结果时，使用确定性提取的当前或最近岗位名称进行唯一匹配。
  - 岗位无法唯一判断时保留候选排序并进入人工确认队列。
  - 专业方向岗位名称包含通用岗位名称时，按唯一最长候选岗位名称归类，例如“体操教练”和“跑酷教练”归入“教练”。
