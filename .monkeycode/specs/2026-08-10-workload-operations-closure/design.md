# 工作量运营闭环增量设计

Feature Name: `workload-operations-closure`
Updated: 2026-08-10

## 设计说明

在现有工作量治理链路上增加一个幂等的 CLI 入队入口。目标计算由统计服务把岗位项目规则中的 `target_value` 转换为周期目标，并在项目汇总、门店汇总和员工汇总中统一返回。

## 组件

- `api/workload/queue-alert-job.php`：校验 CLI、业务日期和任务队列状态，在事务中入队。
- `WorkloadMetricSelectionService`：读取当前规则目标并计算周期目标、差额和达成率。
- `admin/workload.html`：显示运营化标签和目标/实际/差额列。

## 目标计算

```text
周期目标 = 单日目标 × 应交日报义务数
目标差额 = max(0, 周期目标 - 实际有效值)
目标完成率 = min(1, 实际有效值 / 周期目标)
```

无目标项目返回 `target_status = unset`，目标为零，差额为零，完成率为零。

## 正确性约束

- 相同业务分钟最多保留一个 `workload.alert.run` 队列任务，支持一天内多次检查。
- 项目目标计算使用同一条岗位项目规则和同一组应交义务。
- 页面只消费接口返回的目标字段，不在浏览器端重新推算业务口径。

## 验证

- 使用 PHP lint 检查新增和修改的 PHP 文件。
- 使用现有工作量接口测试验证目标字段和缺省目标状态。
- 使用静态检查确认后台关键标签已完成运营化替换。
